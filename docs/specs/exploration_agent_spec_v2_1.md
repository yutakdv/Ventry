## 0. 정의와 원칙

### 0-1. 무엇인가
사용자가 묻지 않은 인접 시나리오(예산 ±, 지역 확장, 업종 스왑, 권리금 조건)에 대해
에이전트가 **결정 지형 전체를 해석적으로 계산**하고, 의사결정 경계(선택지가 유의미하게
바뀌는 지점)와 그 경계를 넘는 현실적 수단(자격 부합 조달 상품)을 찾아 보고하는 기능.

- 완성 문장(상향, v2): "예산 1,320만 원을 추가 확보하면 **진입 가능 후보는 3곳 → 11곳**으로
  늘어납니다. 다만 해당 금액을 ○○보증(연 2.5%, 5년 상환 가정)으로 조달할 경우 월 상환
  부담을 반영하면 **지속 안정 후보는 7곳**입니다. 자격 요건 부합 여부만 확인된 것이며,
  한도와 승인은 기관 심사 사항입니다."
- 완성 문장(하향): "예산을 6,480만 원까지 낮춰도 현재 후보 3곳이 전부 유지됩니다.
  차액을 예비 운영자금으로 두면 지속 여력 지표가 개선됩니다."

### 0-2. 불변 원칙
1. **모든 숫자는 결정적 계산이 만든다.** LLM은 (a) 탐색 축 우선순위 계획, (b) 구조화 결과의
   언어화, (c) 리스크 검증 반박문 생성만 담당. 수치 생성·재계산 금지.
2. **탐색이 아니라 유도다.** 경계는 샘플링이 아닌 닫힌 형태 계산으로 얻는다 (§2).
3. **보고는 선택이다.** 프론티어 전체를 계산하되 보고는 최대 3건. 0건도 유효한 결과.
4. **차입 확대의 비용을 함께 말한다.** 상향 인사이트는 반드시 (a) 한계 조달의 상환 부담을
   반영한 지속 후보 수, (b) 하향 안전 마진, (c) 정보 제공 고지와 함께 노출. (금소법 적합성
   원칙 방어 — 표현 수위는 §7)

## 1. 탐색 축과 LLM 탐색 계획

| 축 | 기호 | 계산 방식 | 비용 |
|---|---|---|---|
| A1 예산(상·하향 통합) | B | 해석적 프론티어 (§2) — 실행 1회로 전 구간 | 정렬 1회 |
| A2 지역 확장 | R | 인접 자치구별 프론티어 재계산 | ×2~4 |
| A3 업종 스왑 | I | 타 업종 프론티어 재계산 | ×1~2 |
| A4 권리금 조건 | P | cost_ex_premium 기준 프론티어 (A1의 부산물) | 0 |

- **LLM 탐색 계획 단계 (신규)**: 세션의 대화 맥락·프로필을 입력으로, LLM이 A2~A4의 실행
  여부와 우선순위를 결정한다. 예: 사용자가 "권리금이 제일 걱정"이라 말했으면 A4 결과를
  최우선 보고 슬롯에 배정. 액션 공간이 유한(축 4개 × 실행/스킵/우선)하므로 환각 통로 없음.
  이 단계가 "룰엔진 아니냐"에 대한 구현된 답변이다 — 대화 맥락 기반 계획은 룰로 못 쓴다.
- A1은 계획과 무관하게 항상 실행 (서비스 핵심).
- 축 조합 탐색 금지 (v1 동일): 단일 축 변화만이 실행 가능한 조언이 된다.

## 2. 알고리즘 — 해석적 이중 프론티어

### 2-1. 진입 프론티어 (닫힌 형태)
대상 (지역 집합, 업종)의 후보 상권 a마다 비용 중앙값 c_a(권리금 포함), c'_a(제외)가
사전 계산 테이블에 존재한다. 진입 필터는 "c_a ≤ B" 비교이므로:

```
후보 비용 배열 정렬: c_(1) ≤ c_(2) ≤ ... ≤ c_(n)
N_entry(B) = |{a : c_a ≤ B}|          ← B에 대한 계단 함수, 점프 지점 = c_(k) 값 자체
```
- **그리드 불필요, 오차 0.** 다음 경계 = min{c_a > B₀}, 갭 = 그 값 − B₀ (원 단위 정확).
- 하향 안전 마진 B_safe = max{c_a : c_a ≤ B₀} — 현재 후보 중 최대 비용, 정확값.
- 무권리 프론티어는 c'_a 배열로 동일 계산 (추가 비용 0).
- N_entry(B)는 B에 대해 단조 비감소 — 진입에 한해서만 성립한다. **지속은 아니다 (§2-3).**

### 2-2. 조달 검증 — 조합 제약 (v1 §2-3 대체)
경계 B₁에 대한 gap = B₁ − B₀ 의 커버 수단을 다음 제약 하에 탐색:

1. **잔여 한도 원칙**: B₀ 구성(자기자본 + 확정 상품별 사용액)을 세션에 기록. 커버 재원은
   ① 확정 상품의 미사용 한도 → ② 자격 통과 + status=open 미포함 상품 순.
2. **중복수혜 제약**: 상품 메타의 `exclusive_group` 필드(동일 그룹 내 1개만 수혜 가능,
   예: 동일 기관 운전자금 중복 금지)를 검사. D2 정책자금 구조화 시 필드 추가 — 전건 검수
   항목에 포함.
3. 커버 불가 경계는 보고 제외. "돈이 더 있으면 좋다"는 인사이트가 아니다.
4. 커버 성공 시 **한계 조달 명세** 확정: {상품, 금액, 금리 r, 상환기간 T(상품 조건 또는
   보수 가정 5년 — assumptions.md 등재)}.

### 2-3. 지속 프론티어 — 확장 부담률 (v2 핵심 신설)
한계 조달의 월 상환액 m(gap, r, T)을 원리금균등 공식으로 계산하고, 부담률 필터를 확장한다:

```
기존 필터 2:   환산임대료 / 월 추정매출 ≤ θ
확장 필터 2':  (환산임대료 + m) / 월 추정매출 ≤ θ'      (θ' 초기값 = θ + 5%p, 출처 과제)
N_sustain(B₁) = |{a : c_a ≤ B₁  AND  확장 필터 2' 통과}|
```
- **N_sustain은 B에 대해 단조가 아니다.** 차입으로 B를 늘리면 m이 모든 후보의 고정비를
  올리므로, 진입 후보가 늘어도 지속 후보는 줄 수 있다. 이 비단조성이 서비스 철학
  ("버틸 수 있는 곳")의 수학적 구현이며, T1 인사이트는 두 수를 반드시 병기한다.
- 자기자본만으로 B를 구성한 구간에서는 m=0 → 필터 2와 동일 (일관성 확인 테스트 케이스).
- θ' 출처: 임계 문헌 확인(D1 과제)과 동일 트랙. 실패 시 "통용 기준 + 화면 조정 가능" 후퇴.

### 2-4. 인사이트 스코어링 & 컷 (목적함수 v2)
```
Q(경계)  = α·ΔN_green + β·ΔS_top + γ·ΔN_sustain     # 품질가중 임팩트 (🟢·상위점수·지속 중심)
F(경계)  = 조달 커버 완전성 × 조건 단순성
C(경계)  = 1 + (m / 월 추정매출 중앙값)               # 조달 비용 페널티
score    = Q × F / C
```
- v1의 ΔN≥3/50% 임계 폐기 → **품질 조건**으로 대체: ΔN_green ≥ 2 또는 ΔS_top이
  상위 백분위 1구간 이상 개선. (N₀=1→2 같은 무의미 발동, 저품질 대량 편입 발동 차단)
- 보고: score 상위 2건(T1/T3/T4/T5 중) + T2 안전 마진 1건 = 최대 3건 고정.
- 전 경계 임계 미달 시 0건 보고: "인접 시나리오를 전 구간 검토했으나 현 조건 대비
  유의미한 대안이 없습니다. 현재 예산은 안정 구간입니다."

### 2-5. 언어화 (LLM 개입 지점 2/3)
- 입력: 인사이트 JSON. 프롬프트 제약: "입력에 없는 수치·상품·조건 언급 금지."
- **템플릿 우선 원칙 (v2)**: 결정적 계산 직후 템플릿 문장(f-string 조립)으로 즉시 스트리밍
  → LLM 문장은 도착 시 교체 이벤트로 전송. LLM 장애·지연 시 템플릿이 최종본 — 데모 무중단.
- 실시간 LLM 호출 1회 (인사이트 일괄), 타임아웃 5초.

## 3. 인사이트 타입 (5종 고정, 문장 골격 v2)

| 타입 | 조건 | 문장 골격 |
|---|---|---|
| T1 기회 경계 | 상향 경계 + 조달 검증 통과 | "{gap}원 추가 확보 시 진입 후보 {N₀}→{N₁}곳, 상환 부담 반영 시 지속 안정 {N_s}곳. {상품명}({출처})이 자격 요건에 부합합니다 — 한도·승인은 기관 심사 사항" |
| T2 안전 마진 | B_safe < B₀ | "{B_safe}원까지 낮춰도 후보 유지. 차액을 예비 운영자금으로 두면 지속 여력 지표가 개선됩니다" |
| T3 지역 대안 | 인접구 품질 조건 충족 | "{인접구} 확장 시 {지표} 개선. 단 {트레이드오프}" |
| T4 업종 대안 | 업종 스왑 품질 조건 충족 | "동일 예산에서 {업종}은 진입 후보 {N}곳 — 업종 검토 시 참고 정보" |
| T5 무권리 조건부 | ⚪ 상권 존재 | "무권리 매물 확보 시 {N}곳 추가 진입 가능" |

- 타입 추가 금지. "권장/추천드립니다" 등 자문성 술어 금지 — 정보 서술형만 (§7).

## 4. API 계약

```
GET /api/explore/{sid}?v={version}                          (SSE)
  이벤트 순서:
    plan      { axes: ["A1","A4",...], rationale }           // LLM 탐색 계획 결과
    insight   { ...템플릿 headline... }                       // 결정적 계산 즉시, 1건씩
    refine    { insight_id, headline }                        // LLM 문장 교체 (선택적)
    done      { scenarios_explored, frontier_points }

  insight 스키마:
    { type: "T1|T2|T3|T4|T5",
      headline, delta: { n_entry_before, n_entry_after, n_sustain_after, score_delta },
      gap_amount, marginal_payment,                           // T1: 갭·월 상환액(가정 명시)
      funding: { name, amount_max, rate, term_assumed, status, notice_date,
                 exclusive_group, source: { org, url, collected },
                 source_quote: { text, org, doc, date } },         // 원문 인용(§5-4). 청크 없으면 필드 생략
      disclaimer: true }
```
- `version`: 슬라이더 변경마다 프론트가 증가시켜 전달. 서버는 세션의 최신 version이 아니면
  이벤트 전송 전 폐기 (§5 취소).
- `frontier_points`: 계단 함수 좌표 배열 — P1에서 미니 차트("예산-후보 곡선") 렌더 가능.

## 5. 구현 아키텍처 (Spring Boot + PostgreSQL)

| 항목 | 설계 |
|---|---|
| DB 접근 | **탐색 전체에 쿼리 1회**: 대상 (지역 집합 × 업종) 후보 행(비용·점수·임대료·매출) 일괄 조회 → 인메모리 프론티어 계산. 시나리오별 쿼리(N+1) 금지 — 커넥션 풀 병목 원천 차단 |
| 캐싱 | 배치 정적 데이터 → Caffeine 캐시, 키 (업종, 자치구), 기동 시 워밍. 정렬 비용 배열은 배치 단계에서 사전 정렬 저장 가능 |
| 병렬화 | 불필요 (인메모리 <100ms). A2~A4도 동일 캐시에서 계산 |
| SSE | SseEmitter + 전용 비동기 executor (톰캣 워커 스레드에서 LLM 대기 금지). 이벤트 순서: 템플릿 insight 즉시 → LLM refine 후속 |
| 취소 | 세션별 exploration version(AtomicLong). 새 요청 시 증가 → 구 버전 태스크는 이벤트 전송 직전 버전 비교로 자체 폐기. 진행 중 LLM 호출은 결과 무시(비용상 강제 중단 불필요, 타임아웃 5초) |
| 동시성 병목 | 계산 아님 — **LLM 호출이 유일 병목** (지연·레이트리밋·비용). 대응: 템플릿 우선으로 LLM을 필수 경로에서 제거 + 세션당 동시 탐색 1건 + LLM 세마포어(동시 K건) |
| 재실행 | 슬라이더 debounce 300ms 후 1회. /recommend와 /explore는 동일 version 공유 |

## 7. 표현 수위 — 컴플라이언스 (전 화면·문서 공통)

| 금지 | 대체 |
|---|---|
| "조건부 승인" | "조건부 적합" (판정 4단계: 적합 / 조건부 적합 / 유의 / 범위 외) |

## 9. 심사위원 예상 질문 10 + 30초 답변

1. **"N(B) 단조 가정은 언제 깨지나?"** — 진입 후보는 단조입니다. 지속 후보는 아닙니다.
   추가 차입은 월 상환액으로 모든 후보의 고정비를 올리므로, 저희는 진입/지속 이중
   프론티어를 분리 계산하고 두 수를 병기합니다. 이 비단조성이 저희 서비스 철학의 수학적
   구현입니다.
2. **"경계 수치가 정확한가? 그리드 오차는?"** — 그리드를 쓰지 않습니다. 경계는 후보 상권
   비용의 정렬값 그 자체라 닫힌 형태로, 원 단위 오차 0으로 계산됩니다. 다만 비용 자체가
   출처 명시된 추정 구간이므로 경계도 구간으로 함께 표시합니다.
3. **"이건 룰엔진 아닌가?"** — 숫자를 만드는 계층은 의도적으로 결정적입니다. 금융에서
   숫자는 검증 가능해야 하니까요. AI는 룰이 못 하는 세 가지를 합니다: 대화 맥락 기반
   탐색 계획, 결과의 언어화, 추천에 대한 데이터 기반 반박 생성. 설명가능성이 요구되는
   금융 AI에서 이 분리는 타협이 아니라 설계입니다.
4. **"대출 확대를 유도하는 것 아닌가?"** — 상향 인사이트는 단독 노출이 불가능하게 설계돼
   있습니다. 한계 차입의 상환 부담을 반영한 지속 후보 수, 하향 안전 마진, 정보 제공 고지가
   항상 동반됩니다. 저희는 '더 빌려라'가 아니라 '빌리면 무엇이 달라지는가'를 보여줍니다.
5. **"초기비용 추정을 어떻게 믿나?"** — 4개 블록 전부 공공 통계 출처 기반이며 구간+추정치
   라벨+권리금 이중 표기로 화면에 상시 노출됩니다. 확정치가 아니라 의사결정용 구간입니다.
6. **"조달 매칭이 실제 한도를 보장하나?"** — 보장하지 않고, 보장한다고 말하지 않습니다.
   자격 요건 부합 여부만 구조화 데이터로 판정하며, 한도·승인은 기관 심사 사항이라는 고지가
   모든 문장에 붙습니다. 저희는 상담으로 연결하는 관문입니다.
7. **"LLM 환각은?"** — LLM은 수치를 만들 수 없는 위치에 있습니다. 입력 JSON에 없는
   수치·상품 언급을 금지한 언어화만 담당하고, 장애 시 템플릿 문장이 최종본이 됩니다.
   시연은 LLM이 전부 죽어도 완주합니다.
8. **"동시 사용자가 늘면?"** — 계산은 탐색당 DB 1회 + 인메모리 100ms라 병목이 아닙니다.
   병목은 LLM 호출인데, 템플릿 우선 설계로 필수 경로에서 제거했습니다.
9. **"데이터가 분기 단위인데 괜찮나?"** — 입지·자금 규모는 구조적 의사결정이라 분기
   신선도로 충분하며, 화면에 데이터 기준일을 상시 표기합니다.
10. **"KB에 내재화되면 뭐가 달라지나?"** — 지금은 공개 통계로 상환 부담을 가정 계산하지만,
    행내 여신 데이터와 결합하면 확장 부담률이 실제 상환 능력 기반으로 정밀화되고, 기존
    여신 고객의 이전·운영 컨설팅으로 확장됩니다. 공개 데이터 프로토타입이 내재화 시너지의
    하한선입니다.
