# 심사 예상 Q&A (19문항)

발표가 없으므로(수상 제출물 3종 확정) 이 문서는 리포지토리 동봉용이다.
핵심 5문항은 기술설명서 본문 「설계 원칙」 박스로 선제 반영(스펙 §0-6-3), 나머지는 여기서 상세화.
본선 진출 시 이 문서가 그대로 발표 Q&A 대비 자료로 승격된다 (스펙 §11).

## A. 핵심 9문항 (스펙 §11 — D13~14에 답변 최종화)

1. **"이 예산이면 이 상권이 된다는 근거는?"** — 4블록 출처 기반 추정 + 구간 표기 + 이중 필터. *(상세 답변 작성: CM-05)*
2. **"AI가 하는 일이 정확히 뭔가?"** — 3단계: ①사용자 이해 ②결정공간 탐색 ③결과 검증. 숫자는 결정적 계층.
3. **"기존 상권분석과 뭐가 다른가?"** — 질문 자체 뒤집기 + 결정 지표 전체 계산 + 상환 부담 반영.
4. **"추천이 맞는지 어떻게 아나?"** — 가중치 공개·조정 가능 / 민감도 분석(±20%·θ 변동) / 검증 에이전트 / 오프라인 ML 교차 검증(게이트 통과 시만 부록 2 수록).
5. **"대출 한도를 어떻게 보장하나?"** — 보장하지 않음. 자격 부합 확인만, 상담 관문.
6. **"대출을 더 받으라고 유도하는 것 아닌가?"** — 상향 인사이트는 지속 후보 수·하향 마진·고지와 항상 동반.
7. **"결국 파라미터 룰 아닌가?"** — 탐색 계획은 대화 맥락 기반 LLM 판단 / 비용 정렬 닫힌 형태 + 조달·지속 제약 최적화.
8. **"임대료가 상권 단위 평균인데 정확한가?"** — 의도된 해상도 설계(역할 분담 서사) + 출처·해상도 화면 표기.
9. **"교통·생활 인프라는 어떻게 반영하나?"** — 대중교통 접근성 = w1 3성분(승하차×거리 감쇠), 생활 인프라 = 집객시설. 매핑 표 제시.

## B. 탐색 상세 10문항 (exploration spec §9 전사 — 답변 완성본은 해당 문서 참조)

10. N(B) 단조 가정은 언제 깨지나 → 지속 프론티어는 비단조 (서비스 철학의 수학적 구현)
11. 경계 수치의 그리드 오차 → 그리드 없음, 정렬값 자체가 경계 (오차 0)
12. 룰엔진 아닌가 → LLM 3역할 분리는 금융 AI의 설계
13. 대출 한도 유도 아닌가 → 단독 노출 불가 구조
14. 초기비용 추정 신뢰 → 공공 출처 4블록 + 구간 + 이중 표기
15. 조달 매칭이 한도를 보장하나 → 비보장 명시, 고지 동반
16. LLM 환각은 → 수치 접근 불가 구조 + 템플릿 폴백
17. 동시 사용자 확장성 → 세션당 DB 1회 + 인메모리 100ms, 병목은 LLM(필수 경로에서 제거)
18. 분기 데이터 한계 → 구조적 의사결정에 충분 + 기준일 표기
19. KB 내재화 시 → 행내 여신 데이터 결합 로드맵 (경쟁이 아니라 결합)

## 설계 원칙 박스 5 (기술설명서 본문 선제 배치 — 스펙 §0-6-3)

| 박스 | 배치 장 | 요지 |
|---|---|---|
| ① 룰엔진? | 아키텍처 | 숫자 계층은 의도적 결정적 + ML 교차 검증(부록 2) + 서빙 무모델 |
| ② 대출 유도? | 탐색 | 상향 인사이트 단독 노출 불가능 설계 |
| ③ 임대료 해상도? | 데이터 | 병별상 구역 해상도, 상단 시스템은 상권 해상도 — 역할 분담 |
| ④ 한도 보장? | 자금 매칭 | 보장하지 않으며, 보장한다고 말하지 않는다 |
| ⑤ 추천 신뢰? | 점수화 | 가중치 공개 + 민감도 + 검증 에이전트 + 평가 하네스·ML 교차 검증(부록 1·2) |
