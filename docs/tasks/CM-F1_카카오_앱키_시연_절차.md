# CM F-1 — 카카오맵 앱키 시연 환경 주입 절차

**이슈 #107** (CM 통합 리포트 F-1, P0) 의 결론 문서. **코드 결함이 아니라 절차 문제**다 —
앱키 발급·도메인 등록은 이미 끝났고 FE 로컬에서 카카오맵이 정상 렌더되는 것을 확인했다.
남아 있던 것은 「시연 머신에 누가·언제·어떻게 키를 넣는가」였고, 이 문서가 그것을 확정한다.

---

## 0. 왜 P0 인가

지도는 화면 3의 본체다. `VITE_KAKAO_APP_KEY` 가 비면 FE 는 우측 목록으로 **우아하게
폴백하고 원인 문구까지 띄우지만**, 그 폴백이 심사에서 정상 동작으로 읽히지는 않는다.
설계가 잘 돼 있는 것과 심사위원 눈앞에 지도가 있는 것은 다른 문제다.

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| **누가** | 시연 머신을 조작하는 사람이 직접 넣는다. 별도 담당을 두지 않는다 — 키가 로컬 `.env` 에만 존재하므로 **머신 조작자 = 주입자**여야 전달 단계가 생기지 않는다 |
| **언제** | **리허설 전**(CM-05 1차 리허설 시작 시점). 당일 아침이 아니라 리허설에서 실물로 확인해야 실패가 드러난다 |
| **어떻게 전달** | 저장소에 올리지 않는다. 카카오 개발자 콘솔에서 **그 자리에서 다시 복사**한다 — 키를 메신저·문서로 옮기지 않는 것이 가장 단순한 전달 경로다 (재발급 아님, 조회만) |
| **확인 방법** | 아래 §3 체크리스트. 리허설 체크리스트(CM-05)에 포함 |

## 2. 주입 절차

```bash
# 1) 루트 .env 준비 (없으면)
cp .env.example .env

# 2) 콘솔에서 JavaScript 키 복사 → .env 의 해당 줄에 붙여넣기
#    https://developers.kakao.com/console/app → 앱 선택 → 앱 키 → JavaScript 키
#    VITE_KAKAO_APP_KEY=<붙여넣기>

# 3) 반드시 --build 로 재기동
docker compose up --build
```

### ⚠️ `--build` 가 필수인 이유

`VITE_KAKAO_APP_KEY` 는 **빌드 타임 주입**이다(`docker-compose.yaml` 의 `web.build.args`).
Vite 가 번들에 값을 굽기 때문에 **컨테이너만 재시작해서는 반영되지 않는다.**

```
docker compose restart web     ❌ 옛 번들 그대로 — 지도가 계속 비어 있다
docker compose up --build      ⭕ 번들 재생성 → 키 반영
```

dev 서버(`npm run dev`, :5173)는 런타임에 읽으므로 이 제약이 없다. **시연은 :3000(compose)
경로로 하므로 이 함정에 걸리는 쪽은 시연 환경이다.**

### 도메인 등록 (이미 완료 — 머신을 바꿔도 그대로다)

카카오 콘솔 → 플랫폼 → Web 에 아래 두 개가 등록돼 있어야 한다. 등록은 **앱 단위**라
시연 머신이 바뀌어도 다시 하지 않는다.

```
http://localhost:3000     # compose 경로 (시연)
http://localhost:5173     # dev 서버 (개발)
```

## 3. 확인 체크리스트 (리허설·당일 공통)

- [ ] `docker compose up --build` 완료 후 `http://localhost:3000` 접속
- [ ] 화면 1 → "데모 프로필 불러오기" → 화면 2 → 예산 1억 확정 → **화면 3 진입**
- [ ] **지도에 판정 색 마커가 그려진다** (회색 안내 상자가 아니다)
- [ ] 마커 클릭 시 말풍선이 뜨고 상권명·환산 임대료가 보인다
- [ ] 브라우저 콘솔에 `[kakao] SDK를 찾을 수 없습니다` 경고가 **없다**

### 실패했을 때 읽는 법

| 화면 | 원인 | 조치 |
|---|---|---|
| 지도 자리에 점선 상자 + "지도를 불러오지 못했습니다" | 키가 비었거나 번들에 안 구워졌다 | `.env` 값 확인 → `--build` 재기동 |
| 상자는 없는데 타일이 회색 | 도메인 미등록 | 콘솔 플랫폼(Web)에 `http://localhost:3000` 추가 |
| 콘솔에 401/403 | 키가 틀렸거나 '카카오맵 사용 설정' OFF | 콘솔에서 카카오맵 ON 확인 |

> 지도가 끝내 안 뜨면 **시연은 그대로 진행한다** — 우측 목록·근거 패널·탐색 인사이트가
> 전부 살아 있고, 폴백 문구가 원인을 밝힌다. 판정·수치는 지도와 무관하게 동일하다.

## 4. 남는 위험

- **키는 저장소에 없다.** 새 머신에서 `git clone` 후 바로 `docker compose up --build` 하면
  지도가 빈다 — 이 문서 §2 를 거치지 않으면 재현되는 정상 동작이다.
- 심사위원이 **직접 클론해 돌리는 경로**에서는 지도가 비는 것이 기본값이다. README 는
  이 경우를 「API 키 없이도 전 동선이 동작합니다」로 이미 고지하고 있고, 지도 폴백도
  같은 성격이다.
