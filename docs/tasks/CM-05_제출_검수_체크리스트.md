## C. 재적재 파급 — 덤프를 다시 구우면 **함께** 움직이는 것

`db/init/10_data_core.sql` 또는 `20_finance.sql` 을 재생성했다면 전부 확인한다.
하나라도 빠뜨리면 제출물에 틀린 숫자가 남거나 통합 QA 가 깨진다.

| ✅ | 대상 | 확인 방법 |
|---|---|---|
| ☐ | 도슨트 대본 상위 후보 3곳·진입 곳수 | `README.md` · `scripts/qa_integration.py` `DOCENT` · `docs/tasks/CM-04_도슨트_테스트_프로토콜.md`. **D1 이 정확 일치로 단언**하므로 미갱신 시 반드시 실패한다 |
| ☐ | 평가 하네스 지표 | `make eval` 재실행 → `docs/부록1_2_평가성적표.md`(산출 시각 헤더 포함) · `docs/기술설명서_원고.md` |
| ☐ | 랜딩 하드코딩 지표 | `landingData.ts` `HERO_OVERLAY` 3개 값 **+ 히어로 캡처 이미지**. 오버레이만 고치면 캡처와 어긋난다 |
| ☐ | `docs/images/demo-*.png` | 화면 캡처의 수치가 현 덤프와 일치하는가 |
| ☐ | 가정 등재 | 변경과 실측을 `docs/assumptions.md` 에 **새 번호**로. 뒤집힌 기존 등재에는 철회 주석 |
| ☐ | 실행 중인 스택 반영 | 덤프가 `TRUNCATE … RESTART IDENTITY CASCADE` 로 시작하므로 `docker exec -i ventry-db-1 psql -U ventry -d ventry < db/init/10_data_core.sql` 후 **`docker compose restart api` 필수** (후보 풀이 Caffeine 캐시에 잡혀 있다) |

> 참고 — **비용 기반 수치는 대체로 불변**이다(진입 가능 곳수·조달 카드 금액·T1 gap).
> 점수·밀도 계열만 움직인다. 문서끼리 비교하지 말고 항상 덤프·`metrics.json` 에서 재계산해 대조할 것.
