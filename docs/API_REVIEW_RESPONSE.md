## 요청하신 3문항 — 먼저 답변

### 1. (진단) `form`에 `monthly_investable` 넣을 수 있나?

**넣었습니다. 3필드 전부요.** 우회안(free_text + 파싱 규칙 합의)은 채택하지 않았습니다.

지적하신 근거가 정확합니다. "250만원"을 LLM이 250 / 2,500,000 / 누락 중 무엇으로 뽑을지가
비결정적이고, 이는 LLM이 수치를 만드는 통로가 되어 **불변 원칙 §0-1과 정면 충돌**합니다.
숫자를 자유 텍스트로 받는 설계는 이 프로젝트에서 성립할 수 없습니다.

```jsonc
{ "form": { "age": 32, "capital": 5000,
            "is_existing_business": false,
            "collateral_available": true,
            "monthly_investable": 250,
            "industry": "cafe", "region_hint": "서울 마포구" },
  "free_text": "권리금이 제일 걱정..." }
```

`parsed_profile`은 이 3필드를 그대로 반향합니다.

한 가지 **정직하게 밝혀둘 것**이 있습니다. 세 필드의 현재 쓰임이 다릅니다.

| 필드 | 지금 | 언제 계산에 쓰이나 |
|---|---|---|
| `is_existing_business` | **즉시 실사용** | 자격 정규칙에 결선 완료. 예비창업자 한정 상품(예: 소진공 청년 전용 창업자금)이 기존 사업자에게 걸러집니다 |
| `monthly_investable` | 기록만 | BE-04 — 한계 조달 월 상환액 m의 상한(`m ≤ 월 투자 가능액`) |
| `collateral_available` | 기록만 | BE-04 — 담보·보증 요구 상품의 커버 판정 |

뒤 둘은 스펙에 담보·상환 여력 축이 아직 없어서, 받아두고 BE-04에서 결선합니다. 계약 문서에도
"현재 판정 미사용, BE-04 예약"이라고 명시해뒀습니다 — 화면에서 "이 값이 결과를 바꿉니다"라고
말하면 안 되는 시점이라서요.

### 2. (예산) `POST /budget`이 프리뷰를 주나, 프론트가 `/recommend` 재호출인가?

**`POST /budget`이 줍니다.** 선호하신 안과 같습니다만, 이유는 부담 문제가 아니라 **원리 문제**입니다.

`/recommend`는 세션의 확정 예산 B₀로 계산합니다. 화면 2 시점엔 B₀가 아직 없어 자기자본으로
폴백하므로, 슬라이더가 가리키는 임의 예산의 프리뷰를 **만들 수가 없습니다.** `?budget=` 쿼리로
우회하면 예산의 진실 원천이 세션과 쿼리로 이중화되어 `/explore`(세션 B₀ 기준)와 어긋납니다.

```jsonc
// POST /api/budget/{sid} 응답
{ "confirmed_budget": 8000,
  "composition": [ … ],
  "preview": { "area_count": 3,
               "rent_range": [198, 456],
               "floating_range": [22800, 38200] } }
```

**필드명을 제안과 다르게 했습니다.** `avg_rent: [120, 230]`은 "평균값의 범위"가 되어 자기모순이라
`rent_range`(진입 후보들의 최소~최대)로 바꿨습니다. `floating_pop` → `floating_range`도 동일 이유.

**`area_count`는 배열이 아니라 정수입니다.** 확정 예산이 단일값이면 진입 후보 수도 하나로
결정되기 때문입니다(진입 프론티어 계단 함수, expl §2-1). "78~142개" 대신 정확히 "3개"가 나옵니다 —
슬라이더를 움직일 때마다 오차 0의 값이 갱신되니 화면에는 오히려 유리할 겁니다.

**B₀는 덮어쓰기입니다.** 화면 2 슬라이더는 debounce 후 `POST /budget`을 반복 호출하시면 되고,
마지막 값이 확정값이 됩니다. 화면 3 슬라이더는 스펙 §7·expl §5대로
`POST /budget` → `/recommend?v=` + `/explore?v=`(동일 version)를 유지해주세요.

진입 후보가 0곳이면 `area_count: 0`이고 두 range는 응답에서 생략됩니다(`non_null` 정책).

### 3. (추천) `/recommend`에 `score`·`total_count`·`summary` 중 어디까지?

**셋 다 넣었고, 요청 안 하신 것도 셋 더 넣었습니다.**

```jsonc
{ "data_as_of": "2026-Q1",
  "total_count": 3,
  "summary": { "avg_rent": 309, "avg_sales": 2100 },
  "areas": [ { …기존…,
    "score": 75,                    // 0~100 정수 = round(Σ wᵢ·축ᵢ × 100)
    "monthly_rent": 198,            // ← 추가 (summary와 짝이 맞아야 해서)
    "est_sales": 1800,              // ← 요청분
    "daily_floating": 24500,        // ← 요청분
    "burden_ratio": 0.11 } ],
  "risk_review": { … } }
```

`score`는 지적하신 대로 **이미 내부에서 계산하고 있던 값**이었습니다. `breakdown`만 내보내고
가중 합 결과를 버리고 있었어요. 그대로 노출했습니다. 등급 구간(90+/80/70/60) 매핑은 프론트 소관입니다.

> 참고로 데모 픽스처 기준 점수는 75/71/70입니다(90점대 아님). 정규화가 서울 전체 백분위
> 가중 합이라 상위 상권도 0.7~0.8대에 형성됩니다 — 실데이터 전환(CP2) 후 분포를 다시 보고
> 등급 구간을 같이 정하시죠.

## 정렬·필터 쿼리 파라미터는 넣지 않았습니다 (요청 정리에는 없었지만 문제 인식에 있어서)

`?industry=&budget=&sort=score_desc` 는 도입하지 않았습니다. 대신 **정렬·필터에 필요한 값을
전부 응답에 실었습니다** — `score`·`monthly_rent`·`est_sales`·`daily_floating`.

이유 둘:
1. 프론트가 왕복 0회로 처리할 수 있고, 그편이 스펙 §7의 "**<100ms 재계산 체감**" 목표에
   유리합니다. 정렬 한 번에 네트워크 왕복이 붙는 게 더 손해입니다.
2. 서버 정렬·필터를 두면 `total_count`·`summary`의 기준 집합이 파라미터마다 달라져서
   "이 total_count는 필터 전인가 후인가"를 계약에 계속 적어야 합니다.

`areas`는 `score` 내림차순으로 정렬해서 보냅니다(기본값 제공). 후보 풀이 커져 페이징이
필요해지는 시점(BE-02 실데이터 전환)에 다시 논의하시죠. **필요하시면 넣겠습니다** — 구현
자체는 10줄이고, 위는 어디까지나 지금 조건에서의 판단입니다.

## 4. `/scenarios` — 요청분 + **계약 버그 1건 잡았습니다**

지적하신 `data_as_of` 누락이 정확했습니다. 공통 규약에 "금융상품 응답에는 `data_as_of` 필수"라고
못박아놓고 정작 상품 스키마에 그 필드가 없었습니다. **계약 자체의 결함**이라 고쳤습니다.

```jsonc
{ "label": "보수",
  "budget": 6500,          // 슬라이더 초기 선택값 (= budget_max)
  "budget_min": 5000,      // 심사와 무관한 확정 재원 합 (자기자본 등)
  "budget_max": 6500,      // budget_min + Σ 상품 한도(amount_max)
  "composition": [ { "type": "equity",    "amount_min": 5000, "amount_max": 5000 },
                   { "type": "guarantee", "amount_min": 0,    "amount_max": 1500 } ],
  "products": [ { "name": "서울신용보증재단 창업보증",
                  "amount_max": 1500, "rate": 2.5, "data_as_of": "2026-Q1",
                  "source": {…}, "source_quote": null } ] }
```

**`budget_min`/`budget_max`의 정의를 임의로 정하지 않고 의미를 부여했습니다.**
하한 = 심사와 무관하게 확보된 재원(자기자본), 상한 = 한도 전액을 활용한 경우.
**이 범위가 곧 화면 2 슬라이더의 가동 범위**입니다 — 그래서 범위로 주는 게 맞습니다.

다만 화면에는 "한도·승인은 기관 심사 사항" 고지가 반드시 동반돼야 합니다(§0-4). 상한이 승인
금액으로 읽히면 안 되니까요. `budget`은 슬라이더 초기값으로 남겨뒀습니다.

`composition[]`은 `{type, amount_min, amount_max}`로 바꿨습니다(게이지 렌더용).
**`POST /budget`의 composition은 `{type, amount}` 단일값 그대로**입니다 — 확정은 단일값이니까요.
두 스키마가 다르다는 점만 주의해주세요.

**금리·조건 표기**: `rate`(연 %)를 넣었습니다. "고정금리/보증 90%" 같은 조건 문구는
AI-06 정책자금 구조화(D6) 산출물에 달렸습니다 — 구조화 필드가 확정되면 그때 추가하겠습니다.

## 5. `/explore` — 요청분 + 축 라벨은 **서버가 보냅니다**

```jsonc
// plan
{ "axes": ["A1", "A4"],
  "axis_labels": { "A1": "예산", "A4": "권리금 조건" },   // ← 추가
  "rationale": "대화 맥락 기반: 권리금 축 우선 검토" }
// done
{ "scenarios_explored": 6, "frontier_points": [[6480,3], …],
  "current_budget": 8000 }                               // ← 추가
```

하드코딩 사전 유지도 제안해주셨는데, **서버 송출로 갔습니다.** 축 이름은 화면 문구이고 화면
문구는 용어 컴플라이언스 대상(§0-4)입니다. 프론트가 사전을 들고 있으면 문구를 정정할 때
두 리포를 동시에 고쳐야 하고, 그게 D11~12 용어 스윕에서 놓치기 딱 좋은 지점입니다.

축은 **A1~A4 4종 고정**입니다(추가 금지, expl §1). 계약 문서에도 표로 등재했습니다:

| 코드 | 라벨 |
|---|---|
| `A1` | 예산 (항상 실행) |
| `A2` | 지역 확장 |
| `A3` | 업종 스왑 |
| `A4` | 권리금 조건 |

`current_budget`은 세션 확정 예산(B₀)이라 예산 확정 전에는 자기자본으로 폴백됩니다.

> 상향 인사이트 노출 규칙(지속 후보 수 + 하향 안전 마진 + 고지 문구 동반)을 이미 반영해
> 구현하셨다는 부분 확인했습니다. `insight.delta.n_sustain_after`와 `disclaimer` 연결도 맞습니다.

## 6. 결과 저장·PDF 보고서 — **스코프 외입니다**

스펙 §0-2가 "PDF 상담 리포트"를 **P2(로드맵)로 명시 이월**한 항목입니다. P2는 "생각하지 못한
것이 아니라 의도적으로 미룬 것"으로 서술하는 축이라, 구현하면 오히려 기획 일관성이 깨집니다.

**엔드포인트 신설하지 않습니다. Step 5 화면은 만들지 않으셔도 됩니다.**
D10 기능 동결까지 남은 공수는 P0 미완료분(BE-04·05, FE-04·05)에 배정하는 게 맞다고 봅니다.

계약 문서에 "스코프 외" 절로 명시해뒀고, `tasks/FRONTEND.md`에도 동일하게 적었습니다.

## 그 밖에 바뀐 것 (요청은 아니지만 알고 계셔야 할 것)

**`burden_ratio`가 파생값이 됐습니다.** 픽스처 상수였던 걸 `monthly_rent ÷ est_sales`로
계산하게 바꿨습니다. 스펙 §4-2의 정의 그대로이고, AI-05 산출물(부담률 분모·분자)과도 정합합니다.
**응답 값 자체는 그대로**이니 프론트 영향은 없습니다.

**데모 픽스처 수치가 바뀌었습니다.** 임대료·매출·유동인구 원자재를 넣으면서 실측 수준으로
재조정했습니다. 판정 결과(🟢 망원·합정 / 🟠 홍대, 연남 ⚪ 조건부 갭 1,320만)는 그대로입니다.
