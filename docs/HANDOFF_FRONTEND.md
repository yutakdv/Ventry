## 2026-07-26 — 실데이터 결선 묶음 (이슈 #87 · #90 · #82 · #76)

정책자금 **26건 실테이블**이 서빙에 물렸다(구 `DemoProducts` 하드코딩 2건). 계약의 **필드 이름·타입·
개수는 하나도 바뀌지 않았고**, 바뀐 것은 값의 의미와 데이터의 다양성이다.

### 1. [조치 필요] 시나리오 카드 `budget` 초기값의 의미가 바뀌었다

- **구**: `budget = budget_max` (한도 전액 활용 가정)
- **신**: `budget = budget_min + 필요분` — 필요분은 해당 업종 후보 상권의 **진입 비용 중앙값 −
  자기자본**이며, 보수 카드는 권리금 제외·적극 카드는 권리금 포함 중앙값을 쓴다.

왜: 가용 상품의 최소 한도가 필요분보다 큰 경우가 흔해(실데이터에서 보증형 최소 한도가 1억),
상한을 기본 선택으로 두면 **과잉 조달이 기본값**이 된다.

**화면에서 할 일**: 슬라이더 초기 위치를 `budget_max`로 계산하고 있다면 **응답의 `budget`을 그대로
쓰도록** 바꾼다. 범위(`budget_min`~`budget_max`)는 그대로이므로 사용자는 상한까지 올릴 수 있다.

```jsonc
// 실측 (자기자본 5,000 · 카페 · 서울 마포구) — 2026-07-26 재확인
{ "label": "보수", "budget": 6713, "budget_min": 5000, "budget_max": 15000 }
{ "label": "적극", "budget": 8398, "budget_min": 5000, "budget_max": 12000 }
```

### 2. [조치 필요] "적극"이 "보수"보다 예산이 크다는 보장이 없다

`label`("보수"/"적극")은 **금액의 대소가 아니라 수단**이다 — 보수는 **보증형만**, 적극은 **전체 상품**을
후보로 본다. 후보 풀이 다르므로 위 실측처럼 **보수 상한(15,000) > 적극 상한(12,000)** 이 나올 수 있다.
가용 상품 구조가 그런 것이지 버그가 아니다.

**화면에서 할 일**: "적극이 더 큰 예산"을 전제한 문구·정렬·강조·아이콘이 있다면 제거한다.
두 카드는 **조달 수단의 차이**로 서술한다. 크기순 정렬도 하지 말 것(계약상 순서는 보수 → 적극 고정).

### 3. [조치 필요] 금리를 알 수 없는 상품이 목록에 실제로 등장한다 — **`rate` 키 자체가 없다**

적재 26건 중 **7건**이 절대 금리를 알 수 없어 **지어내지 않고 비웠다**(스펙 §0-1). 원문 표현은
"은행금리에서 X% 차감"(3건), 보증료율만 고시(2건), "CD금리 + 2.0% 이내" 같은 변동 서술(2건)로
갈린다 — 한 가지 형태가 아니므로 `rate_note`를 파싱해 숫자를 뽑으려 하지 말고 **그대로 표시**한다.

> ⚠️ **`rate: null`이 아니라 키 생략이다.** 서버가 `non_null` 직렬화라서 값이 없으면 필드 자체가
> 응답에서 빠진다(계약 공통 규약). `rate === null` 로 분기하면 **영원히 거짓**이 되어 `undefined`가
> 그대로 렌더된다. 판단은 반드시 `rate_type`으로 한다 — 아래 예시의 주석을 보라.

이 상품들은 `matching_products`에는 나오지만 **조달 시나리오 카드에는 편성되지 않는다**
(월 상환액을 못 구해 상환 여력을 검증할 수 없다).

**화면에서 할 일**: `rate`가 없을 때 `0%`·`-`·빈칸으로 렌더하지 말고 **`rate_type`과 `rate_note`로
분기**한다. 표기 예: **"금리 미공시 — 한도·승인은 기관 심사 사항"** + `rate_note` 원문 병기.
`rate_type`은 DDL상 NOT NULL이라 **항상 존재**한다(`"fixed"` | `"variable"`).

```jsonc
// 실측 응답 (2026-07-26). "rate" 키가 아예 없다 — null 이 아니다.
{ "name": "ESG 실천기업 보증", "amount_max": 80000,
  "rate_type": "variable",
  "rate_note": "서울시자금(ESG 자금) 이용 시 은행금리에서 2.5% 차감(서울시 부담)" }
```

`rate`가 있는데 `rate_type: "variable"`인 13건도 있다 — 값은 특정 분기 실값이므로 **`rate_note`의
적용 분기를 함께 노출**해야 한다(기준일 상시 표기 원칙).

### 4. [확인만] 금액 자릿수가 커졌다

목 데이터는 한도가 1,500·3,000만이었으나 실상품은 **최대 80,000만원(8억)** 까지 있다.
`amount_max`·`budget_max`를 렌더하는 자리에서 자릿수 오버플로·줄바꿈이 없는지 확인한다.
(시나리오 카드가 8억 상품을 기본 편성하지는 않는다 — #90 참조.)

### 5. [확인만] 카페 상권의 부담률·환산임대료 값이 내려간다

`v_candidate_area.monthly_rent`의 출처가 업종별 대표면적 기준으로 바뀌어(AI 코드리뷰 #2),
**카페 상권의 `monthly_rent`와 `burden_ratio`가 기존의 약 0.53배**가 된다. 필드는 그대로다.
θ=0.15 통과 상권이 176 → **360곳**으로 늘어 **추천 목록이 길어진다**
(2026-07-26 덤프 재생성 후 실측 360곳 — 최초 공지의 363곳에서 3곳 변동).

### 6. [확인만] `data_as_of`가 `"미상"`일 수 있다

기준일 메타가 없는 소스는 예외 대신 `"미상"` 문자열을 돌려준다(화면 전체가 죽지 않도록).
빈 문자열이 아니라 `"미상"`이므로 그대로 렌더해도 안전하다.

### 7. [확인만] 지역제한 상품이 이제 정상 노출된다

`region_hint`("서울 마포구")와 상품의 `regions`(`["서울"]`) 해상도가 달라 **서울 신청자에게
지역제한 상품이 전부 배제**되던 버그를 고쳤다(#76). 목록에 상품이 갑자기 많아 보이는 것이
정상이다. 현재 덤프의 지역제한 상품은 **25건**(`regions = {서울}`)이고 나머지 1건만 전국이다
— 즉 이 버그는 사실상 상품 목록 전체를 비우고 있었다.

## 2026-07-26 — 원문 인용 결선 (이슈 #18 / BE-06 ①)

### 8. [조치 필요] `source_quote`가 이제 실제로 온다 — 길이를 화면이 통제해야 한다

적재 26건 **전건**이 공고 원문 청크를 보유하므로 `check-area`의 `matching_products`,
`scenarios`의 `products`, `explore`의 `funding` 세 곳 모두에 인용이 실린다.

**서버는 텍스트를 자르지 않는다.** 요약·재작성이 금지인 것은 물론(스펙 §5-4) **길이 자르기도
하지 않는다** — 바이트가 원문과 동일하다는 것이 "인용은 검색이지 생성이 아니다"를 증명하는
유일한 수단이기 때문이다. 그 대가로 길이 편차를 화면이 떠안는다.

| | 실측 (2026-07-26 재확인 · 상품 26건 기준) |
|---|---|
| 최단 | 19자 |
| 중앙값 | 490자 |
| 최장 | **1,863자** |

> 청크 실체는 22종이고 26개 상품이 이를 공유한다(전건이 청크를 갖는다는 사실은 그대로다).
> 청크 22종 기준으로 세면 중앙값 451자다 — 화면 클램프 판단에는 상품 기준 490자를 쓰면 된다.

**화면에서 할 일**: 인용 블록을 3~4줄로 클램프(`-webkit-line-clamp`)하고 "원문 보기"는
`source.url`로 연결한다. 인용문에는 **줄바꿈(`\n`)이 그대로 들어 있다** — 표의 셀 경계가
개행으로 보존된 형태라 `white-space: pre-wrap`으로 렌더해야 읽힌다.

```jsonc
{ "name": "…", "amount_max": 80000,
  "source_quote": { "text": "○ 지원대상\n  - 만 39세 이하 예비창업자로서…",
                    "org": "소진공", "doc": "2026_소상공인정책자금_융자공고", "date": "2026-07-21" } }
```

청크가 없는 상품은 **필드 자체가 없다**(non_null 직렬화). `source_quote?.text` 로 접근하고
없을 때는 기존처럼 출처 기관·문서명·기준일만 노출한다.

> 참고: 인용문에 **같은 어절이 3~4번 반복되는 구간**이 보일 수 있다("최대 2억원최대 2억원최대
> 2억원최대 2억원"). PDF가 굵은 글씨를 여러 번 겹쳐 인쇄한 흔적이 텍스트 추출에 그대로 남은
> 것이며, **서버가 지우지 않는다** — 지우려면 본문 글자를 고쳐야 하고 그러면 원문 대조가
> 깨진다. 화면에서도 고치지 말고 그대로 노출한다.

> ⚠️ **2026-07-26 추가 — 인용 4건은 자격 요건 문단이 아니다 (AI 리뷰 #4).** KB 4개 문서가
> 브라우저 인쇄본 웹 페이지라 자격 요건 문장이 원문에 아예 없고, 그 결과 아래가 인용으로 실린다.
>
> | 상품 | 실제 인용 내용 |
> |---|---|
> | F-000 KB소상공인 보증서대출 | 표지 마케팅 (`최대 1억원`×4 반복) |
> | F-001 KB소상공인 신용대출 | 표지 마케팅 |
> | F-002 이자지원 보증서 대출 | 상품 소개 배너 |
> | F-003 소상공인 정책자금대출 | **브레드크럼 내비게이션 19자** (`로그인인증센터 / 소상공인 정책자금대출`) |
>
> **FE 코드 조치는 없다.** 두 가지 이유다.
> ① 데이터 쪽에서 인용을 비우는 방향으로 처리 예정이며(AI 리뷰 4-2), 그러면 `source_quote`
> 필드가 생략돼 이미 구현된 `source_quote?.text` 분기가 그대로 받는다.
> ② `SourceQuoteBlock`은 「자격 요건 원문」 같은 단정 제목 없이 인용문 + 출처(`org · doc · date`)
> + 「원문 보기 ↗」만 렌더하므로 **표기가 이미 중립적이다** — 고칠 문구가 없다.
>
> 다만 F-000이 **데모 동선의 보수 시나리오 카드에 실제로 노출**된다. 심사 시연에서 이 카드를
> 펼쳐 인용을 보여줄 계획이라면, 데이터 수정 전까지는 **표지 마케팅 문구가 뜬다**는 것을 알고
> 동선을 잡아야 한다.

## 2026-07-26 — 통합 QA 결과 (이슈 #23 / BE-07)

### 9. [확인만] `parse_source` 가 항상 `"form_only"` 로 온다

`ParsedResult.tsx:55` 의 「AI 파싱 반영 / 폼 값만 사용」 배지는 앞으로 **항상 "폼 값만 사용"**
쪽으로 뜬다. 서버가 값을 잘못 보내는 것이 아니라, 자유 텍스트 처리가 키워드 매칭이고 LLM
실파싱이 아직 없기 때문이다 — 구 구현은 **키를 지운 스택에서도 `"llm"`** 을 보내고 있었고
그게 사실과 달랐다(가정 #63).

**화면 코드는 그대로 두면 된다.** 분기는 이미 두 값을 다 다루고 있고, LLM 실파싱이 붙으면
`"llm"` 이 다시 나간다. 다만 **배지가 늘 회색(폴백)으로 보이는 것이 정상**임을 알고 있어야
버그로 오인하지 않는다.

### 10. [조치 필요할 수 있음] 추천 후보가 1,061곳이다 — 지도 렌더링 부하

목 데이터 시절 3~4곳이던 `/api/recommend` 의 `areas` 가 실데이터에서 **1,061곳**으로 온다
(카페·예산 9,000만원 기준). 서버는 계약대로 필터 통과 후보 전량을 돌려준다 —
정렬·필터는 프론트 소관이라는 계약 §4 결정 때문이다.

전송량은 서버에서 해결했다(gzip, 769 KB → 125 KB). **남은 것은 렌더링 부하**다.

**화면에서 확인할 것**: 카카오맵에 마커 1,000개를 그리는 동선이 스펙 §7의 「<100ms 재계산
체감」을 만족하는가. 필요하면 화면 쪽에서 상위 N개만 그리거나 클러스터링을 검토한다.
서버 페이징은 계약 변경이라 D10 동결 전에는 하지 않기로 했다.

> **2026-07-29 조치 — 상한 100 유지, 그 위에 경계 표시를 얹었다.**
> 마커 상한은 `MAP_MARKER_LIMIT = 100` 으로 그대로 둔다. 여기에 더해 **선택한 상권과 그
> 임대료가 조사된 부동산원 구획의 경계**를 채움 없는 윤곽선으로 그린다 — 화면에 동시에
> 존재하는 폴리곤은 **최대 2개**이고 예산 슬라이더 경로에서는 폴리곤 호출이 **0회**라
> (경계가 판정색에 묶여 있지 않다) 렌더링 부하가 늘지 않는다.
>
> 함께 확인된 것 두 가지 —
> ① **뷰포트 리셋 버그**: `setBounds` 가 `[status, areas]` 의존성 안에 있어 슬라이더를
> 움직일 때마다 지도가 서울 전체로 튕겨 나갔다. 특정 자치구를 확대해 둔 상태가 매번
> 파괴됐다. 초기 1회로 제한하고 「서울 전체 보기」로 명시 복귀하게 고쳤다.
> 실브라우저 확인: 확대 후 슬라이더 조작 → 지도 영역 스크린샷 **픽셀 완전 동일**.
> ② **경계의 가시성 한계**: 상권 중앙 면적이 0.072㎢(한 변 약 268m)라, 후보 전체가 들어오는
> 기본 뷰(서울 전역 ≈30km)에서는 상권 한 변이 **중앙 8.1px** 이고 49%가 8px 미만이라
> 경계가 사실상 보이지 않는다. 선택할 때마다 자동 확대하면 비교 중이던 시야가 무너지므로,
> **「근거 범위로 확대」 버튼**으로 명시 요청하게 뒀다. 구 단위(≈6km)까지 들어가면 상권
> 한 변이 중앙 40px 로 71%가 형태로 읽힌다.
