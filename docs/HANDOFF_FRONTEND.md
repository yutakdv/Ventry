# FE 인계 — 서버 측 변경 공지

BE·AI 작업 중 **프론트가 알아야 하는 변경**만 모은다. 계약 스키마의 단일 진실 원천은
[API_CONTRACT.md](API_CONTRACT.md)이며, 이 문서는 "언제·왜 바뀌었고 화면에서 무엇을 해야 하는가"를
담는다. BE 내부 사정은 [HANDOFF_BACKEND.md](HANDOFF_BACKEND.md).

> 표기 규칙: **[조치 필요]** = 화면 코드 수정이 필요하다 · **[확인만]** = 값만 바뀌고 코드는 그대로.

## 2026-07-26 — 실데이터 결선 묶음 (이슈 #87 · #90 · #82 · #76)

정책자금 **26건 실테이블**이 서빙에 물렸다(구 `DemoProducts` 하드코딩 2건). 계약의 **필드 이름·타입·
개수는 하나도 바뀌지 않았고**, 바뀐 것은 값의 의미와 데이터의 다양성이다.

### 1. [조치 필요] 시나리오 카드 `budget` 초기값의 의미가 바뀌었다

- **구**: `budget = budget_max` (한도 전액 활용 가정)
- **신**: `budget = budget_min + 필요분` — 필요분은 해당 업종 후보 상권의 **진입 비용 중앙값 −
  자기자본**이며, 보수 카드는 권리금 제외·적극 카드는 권리금 포함 중앙값을 쓴다.

왜: 가용 상품의 최소 한도가 필요분보다 큰 경우가 흔해(실데이터에서 보증형 최소 한도가 1억),
상한을 기본 선택으로 두면 **과잉 조달이 기본값**이 된다.

**화면에서 할 일**: 슬라이더 초기 위치를 `budget_max`로 계산하고 있다면 **응답의 `budget`을 그대로
쓰도록** 바꾼다. 범위(`budget_min`~`budget_max`)는 그대로이므로 사용자는 상한까지 올릴 수 있다.

```jsonc
// 실측 (자기자본 5,000 · 카페 · 서울 마포구)
{ "label": "보수", "budget": 6713, "budget_min": 5000, "budget_max": 15000 }
{ "label": "적극", "budget": 8398, "budget_min": 5000, "budget_max": 10000 }
```

### 2. [조치 필요] "적극"이 "보수"보다 예산이 크다는 보장이 없다

`label`("보수"/"적극")은 **금액의 대소가 아니라 수단**이다 — 보수는 **보증형만**, 적극은 **전체 상품**을
후보로 본다. 후보 풀이 다르므로 위 실측처럼 **보수 상한(15,000) > 적극 상한(10,000)** 이 나올 수 있다.
가용 상품 구조가 그런 것이지 버그가 아니다.

**화면에서 할 일**: "적극이 더 큰 예산"을 전제한 문구·정렬·강조·아이콘이 있다면 제거한다.
두 카드는 **조달 수단의 차이**로 서술한다. 크기순 정렬도 하지 말 것(계약상 순서는 보수 → 적극 고정).

### 3. [조치 필요] `rate: null` 상품이 목록에 실제로 등장한다

적재 26건 중 **7건이 `rate: null`** 이다. 전부 "은행금리에서 X% 차감" 형태라 절대 금리를 알 수 없어
**지어내지 않고 비웠다**(스펙 §0-1). 이 상품들은 `matching_products`에는 나오지만 **조달 시나리오
카드에는 편성되지 않는다**(월 상환액을 못 구해 상환 여력을 검증할 수 없다).

**화면에서 할 일**: `rate`가 없을 때 `0%`·`-`·빈칸으로 렌더하지 말고 **`rate_type`과 `rate_note`로
분기**한다. 표기 예: **"금리 미공시 — 한도·승인은 기관 심사 사항"** + `rate_note` 원문 병기.
`rate_type`은 DDL상 NOT NULL이라 **항상 존재**한다(`"fixed"` | `"variable"`).

```jsonc
{ "name": "ESG 실천기업 보증", "amount_max": 80000,
  "rate": null, "rate_type": "variable",
  "rate_note": "서울시자금(ESG 자금) 이용 시 은행금리에서 2.5% 차감(서울시 부담)" }
```

`rate`가 있는데 `rate_type: "variable"`인 13건도 있다 — 값은 특정 분기 실값이므로 **`rate_note`의
적용 분기를 함께 노출**해야 한다(기준일 상시 표기 원칙).

### 4. [확인만] 금액 자릿수가 커졌다

목 데이터는 한도가 1,500·3,000만이었으나 실상품은 **최대 80,000만원(8억)** 까지 있다.
`amount_max`·`budget_max`를 렌더하는 자리에서 자릿수 오버플로·줄바꿈이 없는지 확인한다.
(시나리오 카드가 8억 상품을 기본 편성하지는 않는다 — #90 참조.)

### 5. [확인만] 카페 상권의 부담률·환산임대료 값이 내려간다

`v_candidate_area.monthly_rent`의 출처가 업종별 대표면적 기준으로 바뀌어(AI 코드리뷰 #2),
**카페 상권의 `monthly_rent`와 `burden_ratio`가 기존의 약 0.53배**가 된다. 필드는 그대로다.
θ=0.15 통과 상권이 176 → 363곳으로 늘어 **추천 목록이 길어진다**.

### 6. [확인만] `data_as_of`가 `"미상"`일 수 있다

기준일 메타가 없는 소스는 예외 대신 `"미상"` 문자열을 돌려준다(화면 전체가 죽지 않도록).
빈 문자열이 아니라 `"미상"`이므로 그대로 렌더해도 안전하다.

### 7. [확인만] 지역제한 상품이 이제 정상 노출된다

`region_hint`("서울 마포구")와 상품의 `regions`(`["서울"]`) 해상도가 달라 **서울 신청자에게
지역제한 상품 20건이 전부 배제**되던 버그를 고쳤다(#76). 목록에 상품이 갑자기 많아 보이는 것이
정상이다.

## 미해결 — 화면 판단이 필요할 수 있는 것

- **대환대출이 적극 카드에 편성될 수 있다** (#90 문제 2). 기존 대출을 갈아타는 상품이라
  예비창업자 맥락에 맞지 않으나, `finance_product`에 그것을 나타낼 축이 없어 자격 필터로 거를 수
  없다. D10 동결 전 스키마 변경은 하지 않기로 했다. 화면에서 상품 설명을 충분히 노출해
  사용자가 판단할 수 있게 하는 것이 현재 대응이다.
- **`source_quote`는 여전히 `null`** 이다. 원문 청크 18개는 적재를 마쳤고 상품 26건 전건이
  `doc_chunk_ref`로 연결돼 있으나, 서빙에서 청크를 읽어오는 결선은 BE-06(#18) 범위다.
  CP4(#22)에서 구현/이월이 갈린다 — 이월 시 인용 없이 **출처 기관·문서명·기준일만** 노출한다.
