# P1

1. **SSE 첫 오류 무재시도 목 폴백 — 데모 중 순간 단절 1회로 세션 전체가 "예시 데이터"로 고정**
   (FE + QA P2 병합) — `api/client.ts:130-135, 203-208`. EventSource 자동 재연결 시에도
   `onerror`가 발화해 blip이 종국 실패로 처리되고, 스트림 중간 단절 시 실·목 카드가 한 화면에
   혼합될 수 있다. 조치: `done` 이전 오류는 1회 재연결, 재실패 시 수신분을 비우고 폴백.
   **심사 당일 최대 위험이므로 최우선.**
2. **시연 머신 절차의 사람 의존** (QA) — 앱키 빌드타임 주입·`--build`·`down -v` 중 하나만
   빠져도 빈 지도 또는 헌 데이터로 데모가 진행된다. 조치: 시연 직전 리허설을 **실제 시연
   머신에서** 화면 4 마커 + 대본 수치 사전 점검 통과를 조건으로 수행 (CM-04/05 체크리스트에 결합).
3. **FE 화면 회귀 방어 부재** (FE + QA 병합) — 테스트 0건, 마지막 전 구간 검증은 07-26 수동
   CDP 주행. **상충 조정**: FE 리뷰는 vitest 신설, QA 리뷰는 "지금 신설은 비현실적, CDP 재주행이
   실효적"으로 갈렸다. PM 판정: 남은 5일과 기능 동결을 고려해 **제출 전 CDP 전 구간 재주행
   + 스크린샷 갱신을 필수 조건**으로 삼고, vitest는 계약 참조 구현(`composition.ts`) 1파일
   한정으로 여유 시에만 추가한다 — 계약 위반이 조용히 발생하는 지점이 그 파일뿐이기 때문.
4. **F-002 `rate_type='fixed'` 오분류 가능성** (AI) — 은행금리 연동 상품이 FE 분기 키에서
   '고정'으로 나를 소지. 금융 정보 서비스의 금리 성격 오표기는 심사 감점 리스크. 조치: 판정
   정규식 보강 또는 검수본 수동 확정 후 `make load` 재생성 — 단, 덤프 재생성 시
   재적재 파급 목록(도슨트 대본 수치·랜딩 하드코딩 지표) 동반 점검 필수.
5. **OpenAI HTTP 소켓 타임아웃 부재** (BE) — `OpenAiLlmClient.java:22-27`. 행 장애 시 세마포어
   가드가 우회되어 시연 중 커넥션·스레드가 조용히 누적. 조치: connect 2s·read 5s 지정, 3~4줄.
6. **평가 하네스의 서빙 상수 사본 드리프트** (AI) — 가중치·θ·청크 판정 규칙이 사본이라 한쪽이

# Risk Assessment

**1위 — 심사 당일 실패 모드.** 기능이 아니라 환경이 데모를 죽인다: SSE 순간 단절 → 예시 모드
고정(P1-1), 시연 머신 절차 누락(P1-2). 코드는 "데모 무중단"이지만 폴백이 발동하는 순간 심사위원이
보는 것은 예시 데이터다. 완화책이 전부 P1에 등재되어 있고 비용이 작다 — 이번 주 내 처리 가능.

**2위 — 제출물 문서 정합.** 부록의 모델 한계 문구가 PDF 편집 중 탈락하면 게이트 B의 성립 조건
자체가 무너진다. 수치(gzip·대본·랜딩 하드코딩)가 문서 간에 어긋나면 "재현 가능성"이라는 이
프로젝트 최대 강점의 신뢰가 역으로 깎인다. CM-05 검수 체크리스트로 방어.

**3위 — 프로세스 우회.** 기능 동결일에 미커밋 변경 22파일(+627/−54)이 작업 트리에 있었고,
develop 직접 push는 영역 CI 없이 main으로 자동 승격된다. 리뷰의 결론은 `396b41f` 기준이므로,
미커밋 변경분이 PR·CI를 거치지 않고 들어가면 본 리뷰의 보증 범위 밖이 된다.

일정 리스크는 낮다: 잔여 작업이 전부 검증·문서·소규모 수정이고, 스펙의 파행 대응 시나리오
(§12-4·리스크 #12)도 이미 소진할 필요가 없는 상태다.

# Release Decision

## **Conditional Release**

**이유**: 출시를 차단하는 결함(P0)이 4개 영역 어디에도 없고, 요구사항 충족·계약 정합·컴플라이언스
·재현 가능성이 실측으로 입증됐다 — "Not Ready"의 근거가 없다. 그러나 이 프로젝트의 "출시"는
심사 데모 + 제출물이며, 그 경로 위에 검증되지 않은 실패 모드(SSE 폴백 고정, 시연 절차, 3일 묵은
화면 검증)가 남아 있어 무조건 "Release Ready"를 선언하기에는 이르다.

**조건 (충족 시 Release Ready 전환)**:
1. P1-1 SSE 재연결 수정 + P1-5 OpenAI 타임아웃 수정 (코드, 합계 반나절 이내)
2. P1-3 제출 전 CDP 전 구간 재주행 그린
3. P1-2 실제 시연 머신 리허설 1회 통과
4. P1-4 F-002 금리 표기 확정 (수정 또는 "현행이 옳다"는 근거 등재 중 택일)
5. 미커밋 작업 트리 변경분의 PR 경유 반영 + CI 그린

P1-6(eval 상수)·P1-7(브랜치 보호)은 강력 권장이나 전환 조건에서는 제외한다 — 전자는 현재 값
일치가 확인됐고, 후자는 운영 규율로 대체 가능하다.

# Final Comment

성공 가능성을 높게 본다. 이 프로젝트의 승부처는 "입지 추천을 잘한다"가 아니라 **"금융 정보
서비스가 지켜야 할 것을 지키면서 그것을 증명할 수 있다"** 이고, 그 증명 체계(사전 등재 게이트,
재현 가능한 평가, 3중 컴플라이언스 방어, 실패에서 자란 CI 게이트)가 4개 독립 리뷰에서 일관되게
확인됐다. 심사위원이 가장 만족할 부분은 `make eval` 한 번으로 부록 수치가 재현되고, 게이트
기준이 결과보다 먼저 커밋됐음을 해시로 보여줄 수 있다는 점 — 이는 흔한 "AI 서비스 데모"와의
결정적 차별점이다.

가장 우려되는 부분은 역설적으로 코드 밖에 있다. 심사 당일의 네트워크 한 번, 시연 머신 절차
한 줄, PDF 편집 중 문구 한 개가 5일간 쌓은 증명을 화면에서 지울 수 있다. 남은 기간의 우선순위는
새로운 것을 만드는 일이 아니라 **데모 경로의 단일 실패점 제거와 제출물 정합 검수**다. 위 조건
5건을 마치면 이 프로젝트는 자신 있게 제출할 수 있는 상태가 된다.
