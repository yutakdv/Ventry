## 2. 코드·설정 조치

### 데모 경로의 단일 실패점

- **SSE 첫 오류 무재시도 폴백** (FE P1-1 · 계약 리뷰 P1-2) — `api/client.ts` 의 두 SSE 함수가
  `done` 이전 오류에서 **1회 재연결**(800ms) 후에만 목으로 폴백한다. 재연결·폴백 직전에
  `onReset` 을 호출해 **수신분을 비운다** — 재연결 시 중복, 폴백 시 실·목 혼합을 막는다.
  `Scenario.tsx`·`Explore.tsx` 가 그 신호로 목록을 비운다.
- **동기 API 의 LLM 대기** (BE M-01) — `LlmSettings.SYNC_TIMEOUT = 1.2s` 신설, `ReviewGenerator`
  만 사용. 초과 시 동작은 기존 폴백과 동일(`skipped=true` + 템플릿). 채택 근거는
  [DECISIONS §16 ①](../DECISIONS.md).
- **헬스체크 오보** (BE M-06 · QA Q-03-b) — compose healthcheck 를 `/actuator/health` 로,
  `restart: unless-stopped` 추가, develop-ci 스모크에 actuator 확인 추가.
  **리뷰가 제안한 명령 그대로는 항상 실패한다**는 것을 실측으로 확인해 두 곳을 고쳤다 —
  `CMD-SHELL`(dash 는 `/dev/tcp` 미지원) → `CMD` + `bash -c`, `grep '200 OK'`(Tomcat 이 이유구를
  넣지 않는다) → 본문 `"status":"UP"`. 가정 #103 에 실측 등재.
- **목 폴백 회복 경로 부재** (FE M-14) — 배너에 「다시 불러오기」 추가. 세션을 유지한 채 현재
  화면의 조회만 다시 돈다(`retryToken`). 배너의 비가역성은 유지하고, 재시도 후 새 폴백이
  발생하면 그 사실을 덧붙인다.
- **새로고침 세션 소실 무설명** (FE M-13) — 세션 가드가 `/diagnose` 로 되돌릴 때 안내를 노출한다.
  `sessionStorage` 영속화는 하지 않는다 — 근거 [DECISIONS §16 ③](../DECISIONS.md).
