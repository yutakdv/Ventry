## 2. 통신 검증 — 전 구간 실호출 확인

진단 → 시나리오 → 예산 → 지도 → 역방향 → 탐색을 브라우저에서 클릭 주행하고 네트워크·SSE·
콘솔을 전량 기록했다. **목 폴백 경고는 0건**이다.

| 화면 | 호출 | 결과 | 실데이터 증거 |
|---|---|---|---|
| 1 진단 | `POST /api/diagnose` | 200 | 세션 UUID 발급 (목이면 `mock-` 접두가 붙는다) |
| 2 시나리오 | `GET /api/scenarios/{sid}` SSE | 200 | `scenario`×2 → `done`. 보수 상한 15,000 / 적극 12,000 |
| 3 예산 | `POST /api/budget/{sid}` | 200 | 슬라이더 debounce 재호출까지 확인 |
| 4 지도 | `GET /api/recommend/{sid}?v=2` | 200 | 후보 **1,061곳** (진입 1,041 · 조건부 20) |
| 4 역방향 | `POST /api/check-area/{sid}` | 200 | 자격 부합 상품 21건 + 원문 인용 21건 |
| 4 탐색 | `GET /api/explore/{sid}?v=2` SSE | 200 | `plan` → `insight`×3 → `done`, frontier 91점 |

- **SSE 경로**: nginx가 `proxy_buffering off` + `Connection ""` + `read_timeout 3600s`로 올바르게
  설정돼 있다 (`frontend/nginx.conf`). 이벤트가 즉시 도착하고 `done` 후 EventSource가 정상 종료된다.
- **version 취소**: `v=5` 5건 수신 / `v=3`(구 버전) 0건 — expl §5 폐기 규칙 실동작.
- **리스크 검증 LLM 실동작**: 반박문이 `부담률 0.026`·`추정매출 4101만원` 등 **입력된 계산 결과
  안의 수치만** 인용한다. `applied=true` · `skipped=false`. 판정은 반박으로 바뀌지 않는다 (§5-3).
- **`budget` 초기값**: 상한이 아니라 `budget_min`+필요분(6,713)으로 도착 — 2026-07-26 계약 변경(#90) 반영 확인.
- **보수 > 적극 예산 역전**: 계약 주석이 예고한 케이스가 실제로 발생(보수 15,000 > 적극 12,000).
  화면이 크기순을 전제하지 않아 문제 없다.

## 4. 해결 방안

### 4-1. F-1 — 시연 환경 앱키 주입 절차를 고정한다

앱키 발급·도메인 등록은 이미 끝났고 FE 로컬에서 동작이 확인됐다. 그러므로 **할 일은 개발이
아니라 "키가 시연 머신에 들어갔는지 보장하는 절차"** 다. 키는 계속 커밋하지 않는다.

1. **키 전달**: 앱키는 안전한 경로로만 전달하고 저장소에는 커밋하지 않는다. 시연 머신의 루트
   `.env`에 `VITE_KAKAO_APP_KEY=` 값을 채운다.
2. **도메인 등록 확인**: 시연 머신이 `http://localhost:3000`으로 접속한다면 이미 등록된
   도메인이라 추가 작업이 없다. 다른 호스트·포트를 쓴다면 카카오 콘솔에 그 도메인을 먼저
   등록해야 한다 (`.env.example:16-18`).
3. **재빌드 (가장 빠뜨리기 쉬운 단계)**: 앱키는 Vite 빌드 타임에 주입된다
   (`docker-compose.yaml`의 `args`). `.env`만 고치고 재기동하면 **이전 이미지가 그대로 떠서
   지도가 계속 비어 있다.**

```bash
docker compose up --build web       # 키만 바뀐 경우 web 만 재빌드해도 된다
```

4. **검수 1줄**: 화면 4에서 마커가 렌더되고 콘솔에 `[kakao]` 경고가 없는지 확인한다.
   마커 100개 상한 · 선택 시 2개만 갱신되는 계측이 실키에서도 유지되는지 함께 본다.

> **시연 전 사전 점검 3줄**: "① `.env`에 앱키 있음 ② `--build`로 기동함 ③ 화면 4에 마커 보임".
> 세 줄이면 빈 지도가 나올 경로가 막힌다. 코드가 정상이므로 이 절차만 지키면 F-1은 재발하지 않는다.

### 4-2. F-2 — 유동인구 일평균 환산 + 재적재

계약(`API_CONTRACT.md`)과 FE 라벨이 이미 "일평균"이므로 **계약을 바꾸지 않고 데이터를 맞추는
쪽이 정답**이다. 라벨을 "분기 총 유동인구"로 바꾸는 대안은 계약 수정과 FE 문구 3곳 변경을
동반하므로 택하지 않는다.

**패치 위치**: `ai/batch/load/serving.py`. 유동인구에만 적용한다 — `resident_pop`·`worker_pop`은
재고량이라 나누면 오히려 틀린다.

```python
# 분기 실일수 (20261 = 1~3월 = 31+28+31, 2026 평년)
_QUARTER_DAYS = {"1": 90, "2": 91, "3": 92, "4": 92}


def _quarter_days(quarter: str) -> int:
    """'20261' → 90. 분기 총계를 일평균으로 환산할 때 쓰는 실일수."""
    return _QUARTER_DAYS[quarter[-1]]


# assemble() 안 — TOT_FLPOP_CO 는 분기 총계다(요일·시간대 필드 합 = TOT 로 검증, 1627/1649건).
```
