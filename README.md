# Ventry — "여금 우선" 입지 컨설팅 에이전트

> KB 제8회 Future Finance AI Challenge · 주제 2 「AI 데이터 기반 최적 입지 컨설팅 서비스」

기존 상권분석은 **"어디가 좋은가"** 만 답합니다. 창업자의 진짜 질문은
**"내 한도로 어디까지 가능한가"** 입니다. Ventry는 자금 계획을 먼저 진단하고,
진입 가능·지속 가능한 입지를 결정적 계산으로 판정하며, AI가 그 결과를 계획·해석·반박합니다
— **계산은 도구가, 판단은 에이전트가 합니다.**

스코프: 서울 / 카페·음식점 · 판정 4단계 `적합 · 조건부 적합 · 유의 · 범위 외`

```bash
cp .env.example .env        # 키는 전부 비워 두셔도 됩니다
docker compose up --build   # → http://localhost:3000
```

**[0-A] 카카오맵 앱키가 없어도 전 동선을 완주합니다.** 앱키가 없을 때 화면 3은 이렇게 됩니다:

  추정 매출 · 유동인구 · 부담률 · 초기비용(권리금 제외/포함) · 임대료 출처 줄 · 교통 줄이
  전부 카드 안에 있습니다. 마커를 눌러 얻는 정보와 같은 값입니다.
- 상권 **선택**도 목록에서 그대로 되고, 카드 하단 버튼으로 **역방향 판정**도 열립니다.
- 판정 **범례**와 「조건부 적합 636곳 보기」 버튼, **데이터 기준일** 줄도 남습니다.
- 빠지는 것은 **지도 마커와 상권 경계 폴리곤**, 그리고 그 위의 「서울 전체 보기 / 근거 범위로
  확대」 버튼뿐입니다.

**[0-B] 지도까지 보시려면 (3줄)**

1. 카카오 개발자센터에서 앱을 만들고 **JavaScript 키**를 발급받은 뒤, 플랫폼 > Web 에
   `http://localhost:3000` 을 등록하고 「카카오맵」 사용 설정을 켭니다.
2. 루트 `.env` 의 `VITE_KAKAO_APP_KEY=` 뒤에 그 키를 붙여 넣습니다 (`.env.example` 참고).
3. **`docker compose up --build`** 로 다시 빌드합니다 — 앱키는 **빌드 타임에** 번들로 주입되므로
   `.env` 만 고치고 재기동하면 반영되지 않습니다.

**`OPENAI_API_KEY` 를 비우면** LLM 문장 대신 템플릿 문장이 최종본이 되고, 검증 패널은
"검증 생략"으로 표시됩니다. 수치·판정은 어느 쪽이든 동일합니다 — LLM 은 필수 경로에 없습니다.

**빌드 시간 실측 조건**: 2026-08-01 · Apple M5 Pro · macOS · Docker 29.5.3 — 이미지·빌드 캐시를
전부 지운 상태에서 2회 반복, 전 컨테이너 healthy 까지. 최초 기동의 19초에는 `db/init/*.sql`
자동 적재가 포함됩니다. 캐시가 없는 새 머신에서는 JDK·Node·nginx·PostgreSQL 베이스 이미지
내려받기 + Gradle·npm 의존성 설치가 선행되므로 회선·사양에 따라 **근사치**로 읽어 주십시오
— 느린 회선에서는 몇 분이 될 수 있고, 기다리는 동안 화면이 뜨지 않는 것은 정상입니다.

**화면 크기**: 노트북 기본 창(13인치 1280×800 이상)이면 그대로 맞습니다. 창을 900px 아래로

스코프 밖입니다.

## 3. 3분 도슨트

`http://localhost:3000` 에서 아래 6단계를 따라가시면 됩니다. 오른쪽은 기술설명서 대응 면수입니다.

**1 · 자금 진단** — 「마이데이터 불러오기」 클릭 → 예비창업자 / 만 32세 / 자기자본 5,000만 / 마포 카페 *(08면)*

- 이 화면에는 **LLM이 없습니다.** 폼 + 키워드 파싱으로 결정적입니다 (`parse_source: form_only`).
- 이 버튼은 데모 프로필로 폼을 채우는 연출입니다 — 실제 금융기관 연동은 없습니다.

**2 · 조달 시나리오** — 카드 2장의 조달 구성 내역을 펼쳐 출처·기준일·금리 표기 확인 *(09면)*

- 보수 **8,000만** (범위 5,000~15,000) / 적극 **1억 500만** (범위 5,000~12,000).
- 두 라벨은 **금액의 대소가 아니라 조달 수단**입니다 — 보수는 보증형만, 적극은 전체 상품을 후보로 봅니다.

**3 · 지도 판정** — 예산 **1억** 확정 → 판정 4단계 마커 + 근거 패널

- 지도와 목록은 기본으로 **진입 가능 382곳**만 그립니다 — 확정 예산으로 지금 갈 수 있는 곳(적합 + 유의)입니다.
- **조건부 적합 636곳**은 지도 아래 전용 패널로 분리돼 있습니다. **무권리 매물을 잡아야 열리는 구간**이라 확정 예산만으로는 갈 수 없기 때문입니다.
- 상위 후보: 방이동먹자골목 🟢 적합(83) · 잠실 관광특구 🟢 적합(83) · 화곡역 4번 🟢 적합(82).
- 후보 풀은 **서울 전역**이고, 화면은 진단에서 고른 **자치구(마포구 20곳)를 먼저** 보여줍니다. 「서울 전체로」 한 번이면 382곳 전부로 돌아갑니다.

**4 · 결정공간 탐색** — 화면 3 하단 「결정공간 탐색 열기 →」 → 카드가 스트리밍으로 도착 *(11면)*

> ★ **여기가 핵심입니다.** T1 인사이트가 진입 수와 지속 수를 나란히 적습니다.
>
> "3,869만 원을 추가 확보하면 진입 가능 후보는 **382곳에서 1,014곳**으로 늘어납니다.
> 다만 상환 부담을 반영하면 **지속 안정 후보는 244곳**입니다."
>
> 차입으로 진입 후보가 2.7배가 되는데 버틸 수 있는 곳은 그 4분의 1입니다.
> **이 비단조성이 본 서비스의 은행 관점입니다.**

- 헤더의 **탐색 축**은 LLM 계획(AI 역할 ①)의 결과이고, 그 아래 근거 문구는 **서버 템플릿**입니다 — 수치를 만드는 자리가 아니기 때문입니다.
- 첫 카드의 문장은 잠시 뒤 **LLM이 다듬은 문장으로 교체**됩니다(하단 SSE 로그의 `refine · 문장 교체`). 교체본의 수치가 템플릿과 하나라도 다르면 서버가 응답을 버리므로, **바뀌는 것은 문장뿐이고 숫자는 그대로**입니다.

**5 · 리스크 검증** — 화면 3 목록 위 「왜? · 검증 의견 1건 반영」 클릭 → 반박문 *(12면)*

- 입력 사실에 없는 숫자가 섞이면 서버가 응답을 버리고 템플릿으로 돌아갑니다 (화면에 "검증 생략"으로 표시).

**6 · (선택) 되짚기** — 슬라이더를 9,000만으로 → 진입 가능 382 → **114곳**으로 재계산 / 임의 상권 클릭 → 역방향 판정 + 자격 부합 상품 **11건**(+공고 원문 인용) *(09면)*

<details>
<summary><b>각 단계에서 무엇을 보고 계신 건지 — 상세</b></summary>

- **1단계**: LLM 3역할(① 탐색 축 선정 ② 언어화 ③ 리스크 반박)은 4·5번 화면에서 처음 등장합니다.
- **2단계**: 공고 **원문 인용**은 화면 4의 역방향 판정 패널에 있습니다 (6번).

  자치구 드롭다운에는 25개 구의 후보 수가 함께 있어, 좁혀진 상태에서도 다른 구가 몇 곳인지
  사라지지 않습니다. 진단의 지역 입력은 **지역 한정 상품의 자격 판정**에도 쓰입니다
  (서울 11건 / 서울 밖 1건).
- **4단계**: **실행 가능한 축은 2종으로 고정**입니다 — A1(예산)은 항상, A4(권리금 조건)는 무권리
  경계가 존재할 때. A2·A3은 재계산 대상이 없어 데모 스코프 밖입니다(`assumptions.md` #47).
  **자유 입력을 비워도 같은 축이 나옵니다.** T1 의 근거 상품이 변동금리면 월 상환액을 금액으로
  표기하지 않고 사유 문구를 함께 보냅니다.
- **5단계**: 검증 의견은 상권별이 아니라 **추천 결과 전체에 1건**입니다 (계약 §4).

> 캡처·문서의 「예산 8,000만 / 342곳」은 옛 상수 기준이라 더 이상 재현되지 않습니다.

## 4. 설계 — 계산은 도구가, 판단은 에이전트가

```
[배치: Python]                    [저장]              [서빙: Spring Boot]            [프론트]
서울 상권분석 API ────┐
인허가 시가정보 CSV ──┤
부동산원 임대동향 API ┼─ 전처리(pandas/         ┌─ 인터뷰어(폼 + 자유텍스트 키워드) [1]
서울 교통 데이터 ─────┘  geopandas)  →        │  오케스트레이터(고정 절차)
 (역사마스터·승하차)      PostgreSQL ─────────┼→  └ 결정적 도구 계층:            ─SSE→ React
                         (상권DB+정산테이블)  │     자격필터/비용계산/점수·부담률/    +
                                          │     프론티어/역방향                카카오맵
정책자금 문서→LLM 추출   → 구조화+원문 청크 ───┘  결정공간 탐색(이중 프론티어)   [2]
  +사람 검수                                     리스크 검증 에이전트(1왕복)     [3]
                                                  + 원문 근거 인용(청크 직접 조회)
```

- **모든 숫자는 결정적 계산**이 만듭니다. LLM 역할은 3개뿐: [1] 탐색 축 선정
  [2] 결정공간 탐색 결과의 언어화 [3] 결과 검증(리스크 반박). 수치 생성 금지 —
  세 경로 모두 **출력의 숫자를 입력과 대조해 어긋나면 응답을 버립니다.**
- **자유 텍스트 파싱은 LLM이 아니라 키워드 매칭**입니다(`parse_source: form_only`).
  계약이 금액을 `form`으로만 받으므로 파싱이 만들 수 있는 것은 비수치 관심사뿐이고,
  그건 키워드로 충분합니다 — 필요 없는 자리에 LLM을 두지 않는 것도 설계입니다.
- **서빙 경로에 ML 없음.** LightGBM+SHAP은 오프라인 배치에서 점수 설계를 교차 검증합니다
  (스펙 §12) — 설명 불가능한 모델을 서빙에 넣지 않기 위한 신뢰 계층 분리입니다.
- 실시간 외부 의존은 카카오맵 JS SDK 단 하나. LLM 장애 시 템플릿 문장이 최종본입니다.

| 영역 | 스택 |
|---|---|
| Frontend | React 18 · Vite · TypeScript · 카카오맵 JS SDK · SSE |
| Backend | Spring Boot 4.1 (Java 25) · PostgreSQL 16 · Caffeine · SseEmitter |
| AI/Data | Python 3.11 · pandas · geopandas · LightGBM+SHAP(평가 전용) |
| 인프라 | Docker · docker compose · GitHub Actions |

## 5. 검증 — 전부 재현하실 수 있습니다

```bash
python3 scripts/qa_integration.py                 # 통합 QA 10종 (정상 5 + 경계 3 + 장애 2 + SSE 1)
python3 scripts/qa_integration.py --contract-gate # 실데이터 계약 게이트 11종 (D1 + G1~G10)
cd backend && ./gradlew test                      # 결정적 계층 단위·통합 테스트
```

실데이터 경로에서 계약·불변 원칙이 지켜지는지 경계 조건까지 타격해 본 코드리뷰는
**픽스처 테스트가 통과시키는 결함 27건**(P0 9 · P1 8 · P2 10)과 배치 산출물 정의 결함 9건을
찾았습니다. 전건을 분해해 조치했고, 재발은 위 **계약 게이트 11종**이 막습니다 — 통합 compose
스모크 단계에서 실행됩니다.

검증 기록은 숨기지 않았습니다. [계약 검증 하네스 리포트](docs/QA_REPORT_BE07.md) 와
[브라우저까지 붙인 3파트 통신 검증](docs/QA_REPORT_INTEGRATION_CM.md) 은 **발견해 고친 결함과
남긴 미해결 항목을 함께** 적었습니다.

<details>
<summary><b>AI 품질 평가 하네스 재현 (<code>make eval</code>)</b></summary>

아래 3줄로 기술설명서 부록 A1·A2의 AI 산출물 지표(추출 정확도 · 근거 충실도 · 민감도 ·
설계 교차 검증 모델)가 재산출됩니다. 미실행 시에도 부록 수치로 충분합니다.

```bash
cd ai && python3 -m venv .venv && .venv/bin/pip install -qr requirements.txt
make eval PYTHON=.venv/bin/python     # 산출물: ai/eval/out/{metrics.json, *.png}
```

산출값 대조표는 [docs/부록1_2_평가성적표.md](docs/부록1_2_평가성적표.md) 입니다.

자격 매칭 Precision/Recall은 이 하네스가 채점하지 않습니다. `EligibilityFilter` 는 LLM이
개입하지 않는 결정적 순수 함수라 백엔드 테스트(`cd backend && ./gradlew test`)가 검증합니다
— AI는 AI 산출물만, 결정적 계층은 그 계층의 테스트가. 이 분담 자체가 설계입니다.

LLM 을 전면 차단한 상태의 폴백도 확인하실 수 있습니다.

```bash
OPENAI_API_KEY= docker compose up -d --force-recreate api
python3 scripts/qa_integration.py --only F2
```

> 코드리뷰 원본 2건은 내용을 [docs/assumptions.md](docs/assumptions.md)(#68~#82)로 옮긴 뒤
> 폐기했습니다 — 같은 사실을 두 곳에 두면 한쪽이 낡습니다.

</details>
